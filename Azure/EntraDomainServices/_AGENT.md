# Microsoft Entra Domain Services (AADDS) — Agent Instructions

## What's in this folder

Runbooks and scripts for **Microsoft Entra Domain Services** (formerly Azure AD Domain Services / AADDS) — the fully managed, platform-owned pair of domain controllers that provides domain join, Group Policy, LDAP, and Kerberos/NTLM authentication for legacy AD DS-dependent workloads lifted-and-shifted into Azure, without deploying, patching, or managing any DCs yourself. Covers enablement failures, the one-way synchronization model from Microsoft Entra ID, the required subnet/NSG networking model, local (managed-domain-only) password and lockout policy, forest trusts to on-premises AD DS, and the small set of hard architectural blockers (federation without PHS, guest/external accounts) that have no workaround.

---

## Before responding, also check

- **ActiveDirectory/Troubleshooting/ADLDS** — a completely different product despite the similar name: AD LDS is a standalone, on-premises-only LDAP role with no domain, no cloud sync, and no relationship to Entra ID. If the question involves Entra ID synchronization, NTLM/Kerberos against Azure VMs, or a managed/platform-owned DC, it belongs here, not there.
- **EntraID/Troubleshooting/Connect-Sync** — Password Hash Synchronization is configured in Microsoft Entra Connect, not in Domain Services itself; a federated tenant with sign-in failures tenant-wide needs the PHS fix made there.
- **Networking/NSG-A.md** and **Networking/NSG-B.md** — general NSG rule-evaluation troubleshooting applies, but the managed domain's own NSG is platform-created and must never be manually edited; don't apply general NSG remediation advice to it.
- **Windows/_AGENT.md** — for AD DS deployed directly on Azure IaaS VMs (the self-managed alternative to Domain Services), troubleshooting is standard on-premises-style AD DS, not covered here.

## Common entry points

- **"Nobody can sign in to the managed domain"** → `EntraDomainServices-B.md` Triage step 2 — check federation/PHS posture first, it's a tenant-wide blocker
- **"New hire can't domain-join their VM"** → `EntraDomainServices-B.md` Fix 1 — cloud-only account likely hasn't changed its password since enablement
- **"User is locked out but Entra ID shows nothing wrong"** → `EntraDomainServices-B.md` Fix 2 — lockout state is local to the managed domain only
- **"SAMAccountName sign-in fails intermittently"** → `EntraDomainServices-B.md` Fix 3 — always use UPN format instead
- **"Enablement fails with an application ID error"** → `EntraDomainServices-B.md` Fix 7 — stale app registration from a prior failed attempt
- **"User lost access after being restored from the Entra recycle bin"** → `EntraDomainServices-B.md` Fix 6 — new SID, orphaned ACLs

## Key diagnostic commands

```powershell
# Managed domain control-plane health
Get-AzADDomainService -Name "<domain>" -ResourceGroupName "<rg>"

# Tenant PHS/federation posture
Get-MgOrganization | Select-Object OnPremisesSyncEnabled

# In-domain account state (source of truth for auth issues — never trust Entra ID's view)
Get-ADUser -Filter "UserPrincipalName -eq '<upn>'" -Server "<managedDomainFQDN>" -Properties PasswordLastSet,LockedOut,SID

# NSG baseline check
Get-AzNetworkSecurityGroup -Name "<nsgName>" -ResourceGroupName "<rg>" | Select-Object -ExpandProperty SecurityRules
```

## Key dependency chain

```
Microsoft Entra ID tenant (source of authority)
    │
    ├── Password Hash Sync (hard prerequisite — federated tenants without it: total blocker)
    ▼
One-way background sync (Entra ID → managed domain, automatic, never reverse)
    ▼
Managed domain (2 Microsoft-owned DCs, dedicated subnet + platform NSG)
    ▼
Domain-joined VM / app — authenticates via NTLM/Kerberos/LDAP
    (password expiry, lockout, KRBTGT rotation all evaluated LOCALLY here)
```

---

## Response format reminder (always 3 layers)

1. **Immediate action** — unblock the specific sign-in/enablement failure (Mode B)
2. **Root cause** — which layer failed: tenant sync/PHS, managed-domain-local state, or networking (Mode A)
3. **Prevention** — confirm NSG/route-table state matches the platform baseline, PHS is genuinely current, and cloud-only new hires are told to change their password before their first domain-join attempt
