# Windows — Agent Instructions

## What's in this folder

Windows OS-level issues — update management, security features, performance, networking, and peripheral management.

Covers:
- **Windows Update / WfUB** — WSUS conflicts, dual-scan, update rings, stuck updates, 24H2 upgrade issues
- **BitLocker** — key escrow to Entra, recovery, policy enforcement, suspension
- **VBS / Credential Guard / HVCI** — enabling, conflicts with legacy apps/hypervisors
- **LSA Protection (RunAsPPL)** — VBS-independent PPL protection for lsass.exe, Windows 11 22H2+ silent auto-enablement, blocked smart card/VPN/password-filter plug-ins
- **AppLocker / WDAC** — application control, policy audit mode, blocking legitimate apps
- **Networking** — DNS, DHCP (client and Windows Server DHCP role), proxy, time sync, VPN coexistence
- **DHCP Server role** — scope/superscope architecture, DHCP Failover (hot standby/load balance, MCLT/split-brain safety), DHCP Policies, secure dynamic DNS update credential, JET database backup/repair, audit logging
- **NPS / RADIUS server** — Network Policy Server as RADIUS server/proxy for VPN (RRAS/AlwaysOnVPN) and 802.1X wired/wireless auth, connection request vs. network policy evaluation, NPS Extension for Entra MFA
- **Hyper-V host & VM** — standalone/clustered Hyper-V role, VM state and Integration Services, checkpoints/differencing disks (AVHDX), virtual switches, Live Migration (auth modes, Event ID 21502 family), Failover Clustering integration (CSV, quorum), Hyper-V Replica DR
- **Storage Spaces Direct (S2D)** — hyperconverged storage pool/virtual disk/physical disk health, cache-tier vs. capacity-tier architecture, resiliency types (mirror/parity/nested), Health Service auto-repair, drive replacement, storage-network (RDMA) dependency
- **Volume Shadow Copy Service (VSS)** — requestor/writer/provider snapshot architecture, writer state and freeze/thaw timeout failures, shadow storage exhaustion, SQL Server VSS writer isolation, "Previous Versions" and backup-product dependency
- **Windows Server Failover Clustering (WSFC)** — quorum theory and voting mechanics, disk/file share/cloud witness types, dynamic quorum management, cluster networking (heartbeat, Partitioned vs. Down), node quarantine (Health Service auto-isolation), cluster validation, Cluster-Aware Updating (CAU) — the foundation layer underneath Hyper-V clustering and Storage Spaces Direct
- **WSUS Server role** — SUSDB maintenance (WID vs. full SQL Server engine, reindex, decline-superseded, cleanup), content/metadata consistency (wsusutil checkhealth/reset), IIS WsusPool health (the most common real-world WSUS outage cause), multi-tier hierarchy maintenance ordering — server-side complement to the client-side WSUS-to-WfUB migration topic
- **USB / Peripherals** — policy-driven control, driver management
- **Performance** — boot times, CPU/memory issues, storage health
- **Event log analysis** — systematic log collection and interpretation
- **NTLM Relay to AD CS (PetitPotam / ESC8)** — NTLM authentication coercion (PetitPotam and related MS-EFSRPC/MS-RPRN/MS-DFSNM/MS-FSRVP techniques) relayed to an unprotected AD CS HTTP(S) enrollment endpoint (Certificate Authority Web Enrollment / CES), yielding a legitimately-issued certificate for the coerced identity — Extended Protection for Authentication (EPA) as the primary, non-negotiable mitigation, HTTPS-only enrollment, NTLM restriction as defense-in-depth, and certificate template exposure as a severity multiplier; architecturally distinct from certificate-to-account mapping validation (see `ActiveDirectory/Troubleshooting/CertificateMapping/`)
- **AD CS Vulnerable Certificate Templates (ESC1 / ESC4)** — direct, relay-free template misconfiguration privilege escalation: ESC1 (a template with `CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT` set, a client-authentication-capable EKU, and broad Enroll rights, letting a low-priv principal request a certificate for an arbitrary chosen identity) and ESC4 (a non-admin principal holding WriteDacl/WriteOwner/WriteProperty on a template object, letting them reconfigure any template into an ESC1 shape); detection via native `Get-ADObject`/LDAP-filter queries against the Configuration NC, remediation via subject-name/EKU correction, ACL scoping, and enrollment agent restrictions; architecturally distinct from ESC8 (`NTLMRelayADCS-A.md` — requires coercion/relay) and from auto-enrollment ACL plumbing (`CertificateServices-A.md` — an availability concern, not a security-misconfiguration one)
- **WinRM / PowerShell Remoting** — listener/firewall/auth-path triage (Kerberos vs. NTLM, TrustedHosts scope), GPO-managed WinRM configuration precedence over local `Enable-PSRemoting`, the Kerberos double-hop problem (CredSSP vs. classic constrained delegation vs. resource-based constrained delegation — cross-referenced to `ActiveDirectory/Troubleshooting/KerberosDelegation/`), CredSSP Encryption Oracle Remediation (CVE-2018-0886), and WSMan resource quota exhaustion under automation/CI load
- **Windows Backup for Organizations (Windows settings backup and restore)** — settings/Microsoft-Store-app-list continuity across device refreshes (explicitly NOT file/document backup — that's OneDrive Known Folder Move, `M365/SharePoint-OneDrive/`); three independently-gated capabilities (backup, OOBE restore, first-sign-in restore) each with their own join-type and OS-build minimums; the five unrelated-sounding companion policies (EnableActivityFeed/PublishUserActivities/UploadUserActivities/EnableCDP/AllowConnectedDevices) that silently block backup if any is Disabled; the GPO+CSP mixing anti-pattern; Conditional Access and PRMFA interference during OOBE restore; the July 2026 Enterprise State Roaming management consolidation; and the Windows 11 26H2 default-on-for-backup-only baseline change
- **BranchCache** — WAN bandwidth-optimization caching for SMB/Web/BITS content; distributed cache mode (single-subnet-only WS-Discovery multicast peer sharing) vs. hosted cache mode (centralized, multi-subnet-capable, no per-client OS-version limitation); content-information V1/V2 incompatibility that silently blocks cache sharing between mixed-generation clients in distributed mode; per-SMB-share hash publication as the most common "nothing caches" root cause; the undocumented hard dependency on Offline Files (`CscService`) for SMB caching; and BranchCache's non-support for Delivery-Optimization-sourced Windows Update content on Windows 11
- **Folder Redirection & Offline Files (CSC)** — User Configuration GPO folder relocation to a network share, paired with Offline Files (Client-Side Caching) for offline availability; the User-vs-Computer Group Policy scoping split that's the top cause of "redirection never applied"; Sync Center conflict resolution as expected multi-editor behavior, not data loss; per-user (not centrally enforced) Offline Files pinning state; Always Offline mode (`Configure slow-link mode` Latency=1) vs. adaptive slow-link handling; the documented AppData\Roaming redirection anti-pattern; and the shared `CscService` dependency with BranchCache SMB caching
- **Just Enough Administration (JEA)** — role-scoped PowerShell remoting endpoints layered ON TOP OF (not a replacement for) the WinRM transport covered above: role capability (`.psrc`) authoring — `VisibleCmdlets`/`Functions`/`Providers`/`ExternalCommands`, parameter/value scoping via `ValidateSet`/`ValidatePattern` — and session configuration (`.pssc`) authoring — `RunAsVirtualAccount`/`RunAsVirtualAccountGroups`/GMSA identity choice, `RoleDefinitions`, `RequiredGroups` conditional access, transcription; the unconditionally-additive, most-permissive-wins merge behavior across every role a user's groups map to; non-deterministic role-capability search order when a same-named `.psrc` exists in more than one module (Microsoft's own documented reason to keep names globally unique); the Domain-Admins-by-default virtual account on a Domain Controller vs. local-Administrators-by-default on a member server; and custom `FunctionDefinitions` bodies running OUTSIDE JEA's language-mode constraints by design. Not to be confused with the WinRM listener/transport layer itself (`WinRM-A.md`/`WinRM-B.md`) — "can't connect at all" is a WinRM ticket, "connected but access doesn't match expectations" is a JEA ticket
- **Storage Migration Service (SMS)** — the Inventory → Transfer → optional-Cutover model for migrating file servers to newer hardware/OS versions or Azure VMs; the orchestrator/proxy split and the ~2x transfer-speed benefit of installing the WS2019+ destination proxy; the four-pairing migration-account admin-rights requirement (source+orchestrator, destination+orchestrator, evaluated independently); the permanent, absolute restriction on cutover from any Domain Controller — including SBS/Server Essentials editions that don't visually present as one; the same-domain recommendation for a clean identity cutover; and the two documented ACL-fidelity defects (KB4490481 backup-privilege silent file drops, KB4512534 ACL-ordering that breaks downstream DFS Replication preseeding — cross-referenced to `DFS/Troubleshooting/Replication/Replication-A.md`)
- **Print Server Migration** — the PrintBRM.exe (Printbrm.exe)/Print Management "Migrate Printers" backup-restore-cutover workflow, architecturally the print-specific sibling of Storage Migration Service above but a completely separate tool (SMS never migrates print queues); the `-nobin` + `BrmConfig.xml` `<DriverMap>` pattern for landing legacy drivers onto current vendor packages, now materially more important given the January 2026 change ending Windows Update auto-publishing of new third-party V3/V4 driver packages for Windows 11/Windows Server 2025+; the permanent, structural exclusion of local-bus (USB/LPT/COM) and true plug-and-play printers from restore; cross-architecture language-monitor restore failures; and the two-phase rename cutover that's the only way to preserve client UNC paths with zero client-side reconfiguration, with rollback only possible before source retirement begins
- **iSCSI Target Server** — the native software-defined block-storage-over-Ethernet role (Target/virtual-disk IQN architecture, `.vhdx`-backed LUNs); initiator ACL (IQN/IP/DNS/MAC) as a genuinely separate access-control layer from optional CHAP/mutual-CHAP authentication; MPIO as a correctness prerequisite (not a performance add-on) for any multi-NIC/multi-portal design via MSDSM automatic claim; the clustered-role chicken-and-egg constraint requiring non-iSCSI backing storage (Fibre Channel/SAS/Storage Spaces) for the role's own virtual disks; and the documented Event ID 9/20/27/39/153/157 signature of NIC/team boot-timing and driver/firmware-driven session instability — architecturally distinct from Storage Spaces Direct (`StorageSpacesDirect-A.md`, a hyperconverged pool architecture, not a block-protocol target) and from Storage Migration Service (`StorageMigrationService-A.md`, file-level server migration, not a persistent block-storage service)
- **Windows 10 Extended Security Updates (ESU)** — the commercial/organizational Volume Licensing MAK activation path (`slmgr.vbs /ipk` + `/ato` against a Year 1/2/3 Activation ID) for physical Windows 10, version 22H2 devices past the October 14, 2025 end-of-support date; the KB5066791-then-KB5072653 prerequisite install-order requirement; the $61/device Year 1 price doubling annually (cumulative, 3-year max) via Volume Licensing; the separate free-of-charge entitlement for physical endpoints connecting to a Windows 365 Cloud PC (`EnableESUSubscriptionCheck` registry flag deployed via Intune custom policy) as distinct from VM-host-side free ESU (W365/AVD/Azure VM/Azure Local etc.); the activation-endpoint allowlist that's the most common silent blocker; phone/Confirmation-ID and VAMT Proxy Activation for air-gapped devices; and the structural gap that Microsoft stopped providing centralized tenant-wide ESU enrollment reporting after October 15, 2025 — explicitly distinct from the unrelated consumer ESU program (Microsoft Account-based in-Settings wizard) and from Windows Server ESU (a separate program)
